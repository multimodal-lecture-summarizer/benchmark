## 1. Finish qualification without changing the endpoint

For every proposed unit record one canonical `video_id`, dataset source and revision, exact annotation row/record offset and hash, uploader/publisher identity, `course_id`, all `lecturer_ids`, annotation D, probed media D, media URL and SHA-256, rights evidence for internal ASR/frame/OCR/embedding/training, and title/marker parity. Apply the [pre-score boundary rule](rq1-boundary-qualification-rule-260929.md): title mistakes and boundary mistakes have separate statuses; a title mistake alone does not remove a boundary-only unit. For VidChapters, check each original internal `time` against decoded exact publisher media with ±3 s alignment criterion and preserve structural labels in QA. For the candidate Yale publisher-native source, apply its [prospective source amendment](rq1-yale-native-source-amendment-260929.md) and require a strict page-pair adapter before D2. If a media version differs, retain `hold_media`; do not shift GT to fit it. No model predictions or scores are allowed in qualification. Keep rights to redistribute files separate from current research-processing eligibility.

The new `rq1_target_adapter.py` validates published YTSeg `target_ts` against `raw_chapters`, checks the expected annotation/media video ID, and emits only internal starts plus row/hash provenance. Its caller must verify the shard locator and actual media hash/timeline; VidChapters needs an equally strict source adapter before D2. `rq1_official_scorer.py` handles invalid **returned prediction payloads** without dropping a video and records the one-second-grid `k`; 04a/04b now use that policy, including failure counts. Predictor runtime/model errors abort the run rather than masquerading as zero-score real executions. Their predictors receive only source transcript text and validated feature records, not GT columns. The sealed final-test **scoring stage** is now implemented and fixture-tested; candidate inference dispatch remains to be fixed before official use.

The sealed scoring stage `rq1_final_test_runner.py` consumes a versioned lock referencing hashed cohort, history, targets, and candidate configuration plus a prediction artifact bound to that lock/config. It verifies exact candidate-by-video coverage and split/history separation, and writes a non-overwriting report with input/output hashes. `rq1_grouped_bootstrap.py` produces 10,000-resample paired group CIs and separate video-macro deltas; the runner also reports paired-group Cohen's d and group t-test p-values corrected by Holm over locked contrasts. Its `fixture` mode uses synthetic IDs only; the four qualified recruitment units were not used as pilot. Candidate inference dispatch and its code/checkpoint/input receipts still need to be fixed and executed on D2 before an official scoring invocation. `official` mode requires a pretest scale/scope decision in its lock. If too few eligible groups survive, mark the official generalization claim `blocked_data` without opening held-out scores.

### Sealed scoring artifact contract

The `rq1-final-test-lock/1` JSON has `mode`, `run_id`, and `cohort`, `history`, `targets`, `candidate_config` objects, each `{ "path": relative_path, "sha256": digest }`. Official mode also requires a hashed `protocol` object and `scale_decision: pretest_scope_and_precision_locked`. The target JSON is an exact list of test-only `{video_id, reference_sec, duration_sec, annotation_sha256, media_sha256}` rows. Candidate config declares exact candidate names, directed contrasts, `bootstrap_seed`, `bootstrap_resamples: 10000`; official config additionally maps every candidate to code and input-feature SHA-256 execution receipts. Prediction JSON contains `lock_sha256`, `candidate_config_sha256` and one `{video_id, candidate, status, predicted_sec}` row per candidate and test video. Candidate failures retain their video with zero primary F1. The prediction producer must receive source inputs only and be run after the model/configuration lock; the scorer reads GT only after the complete prediction artifact is closed. The runner records runtime code digests, input digests, per-video scores, group CI and final report digest.

Invocation from the nested repo root: `python -m experiments.scripts.rq1_final_test_runner --lock <LOCK_JSON> --predictions <PREDICTIONS_JSON> --output-dir <NEW_FINAL_TEST_DIR>`. The output directory must not exist; reruns use a new run ID and directory. This is a scoring command, not permission to execute the currently blocked official cohort.

Retain pre-run lock receipts alongside post-run artifacts; never overwrite historical qualification ledgers.
