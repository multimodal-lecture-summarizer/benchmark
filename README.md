## Current workflow

1. For each video task, identify a lecture-domain dataset with existing labels that match its target. Verify source, rights, media and annotation provenance. Select candidate model or algorithm families and a common metric.
2. Create an EDA notebook when the dataset is ready. Account for every selected record, inspect relevant inputs and labels, report missingness, duplication, leakage and any sampling limits, then decide whether to keep, repair, restrict or reject the cohort.
3. Create an evaluation notebook after fixing the cohort and protocol. Compare candidates on the same units, ground truth, metrics and resource profile. Save item-level predictions, failures and run receipts. Report `no_selection` when evidence is insufficient.

Since 2026-10-22, general-video datasets with suitable labels qualify for detection and tracking; other tasks keep the lecture-only rule. Create notebooks only for a concrete EDA or evaluation run; a smoke run inside an evaluation notebook is a non-reportable pipeline/budget check, never a placeholder. The [notebook manifest](experiments/notebooks/notebook_manifest.yaml) remains `on_demand` with no pending run; it inventories executed dataset reviews, qualification receipts and evaluation notebooks such as 03b. [The master plan](plans/260901-unified-scientific-benchmark/framework/00-master-plan.md) states the research questions; [the RQ2 plan](plans/261002-0946-rq2-controlled-summarization/plan.md) records the summarization protocol.
